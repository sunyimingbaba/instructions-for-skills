# 三套科研技能的使用指南

更新日期：2026-10-06。这里的“三套”指刚安装到 Codex 全局目录的 Scientific Agent Skills、ARS-Codex 和 Codex Autoresearch。它们都通过对话调用，不需要把技能文件复制进每个论文或代码项目。

## 一、先选哪一个

| 你现在要做的事 | 建议使用 | 原因 |
| --- | --- | --- |
| 找论文、核对 DOI 和发表信息、做图、查统计方法 | Scientific Agent Skills 中的一个专项技能 | 任务明确，直接调用对应技能最省事 |
| 组织一篇论文的实验章节、制定文献综述流程、审稿或规划研究阶段 | `$academic-research-suite` | 它会把任务路由到相应的学术工作流 |
| 对代码反复试验，按一个数字指标判断改动是否有效 | `$codex-autoresearch` | 它会管理测量、试验提交和失败回退 |

三者可以在同一个研究项目中先后使用。例如先用 `$paper-lookup` 核对相关论文，再用 `$academic-research-suite` 规划实验章节；只有当评估命令和优化目标已确定，才考虑用 `$codex-autoresearch` 跑代码迭代。

## 二、共同使用方法

1. 新安装或升级技能后，新开一个 Codex 对话。输入 `$`，查看技能是否出现在列表里。
2. 在提示词里写清楚输入材料、任务、输出格式和约束。比如“只用我给的结果表，不编造数值”“请用简体中文”。
3. 需要访问论文、联网服务、安装依赖或运行实验时，让 Codex 先检查环境；技能说明文件不会自动安装所有依赖。
4. 对论文结果、引用和实验数字，保留可核查的来源或文件路径。生成的文字、图和结论仍需自己核对。

全局技能通常位于 `~/.codex/skills/<技能名>/SKILL.md`。`/skills` 或输入 `$` 可以用于检查当前 Codex 是否识别到它们；如果旧对话没有刷新，直接新开对话。

## 三、Scientific Agent Skills：挑选专项技能

[官方仓库](https://github.com/K-Dense-AI/scientific-agent-skills)。这是一个技能合集，并没有必须先调用的统一入口。本机在 2026-10-06 安装了仓库当时的 177 个独立技能，实际使用时按任务挑选一个或少数几个。

对遥感图文检索论文较常用的入口：

| 技能名 | 用途 | 可以这样提问 |
| --- | --- | --- |
| `$paper-lookup` | 检索论文、核对 DOI、开放获取版本和元数据 | “核对这 10 篇论文的标题、作者、年份、会议和 DOI，附来源链接。” |
| `$literature-review` | 制定检索范围、整理文献和综合研究脉络 | “梳理遥感图文检索中不确定性建模的研究线索，记录检索式和纳入标准。” |
| `$scientific-writing` | 根据已有证据起草、修改或检查科研文字 | “根据我提供的结果表写实验分析，区分事实、解释和局限。” |
| `$scientific-visualization` | 设计、检查科研图表 | “依据这份 CSV 画消融实验图，统一图例、字号和颜色。” |
| `$geopandas` | 处理矢量地理数据与空间分析 | “检查 GeoDataFrame 的坐标系和空间连接逻辑。” |

可复制的提示词：

```text
使用 $paper-lookup，查找 2024–2026 年与遥感图文检索中 Agent、提示学习或不确定性建模相关的论文。
请分别核对论文是否真实存在、发表场所和年份；给出 DOI 或官方论文页。
检索不到的字段标为“未核实”，不要根据标题猜测。
```

```text
使用 $scientific-writing，阅读我给出的实验设置、主结果表和消融结果，起草论文的 Experiments 小节。
只使用已提供的数字；每段说明对应哪一张表或图；最后列出还缺哪些证据。
请用简体中文。
```

注意：不同专项技能可能需要不同的 Python 包、网络或 API 凭据。调用时先读相应 `SKILL.md` 的兼容性和依赖说明；例如文献检索能联网，不意味着所有数据库都能获取全文。

## 四、ARS-Codex：组织学术工作流

[官方仓库](https://github.com/Imbad0202/academic-research-skills-codex)。本机安装版本为 3.23.0。Codex 只注册一个入口 `$academic-research-suite`，内部再按任务选择工作流；不需要寻找单独的 `$academic-paper` 或 `$deep-research`。

| 工作流 | 适用任务 |
| --- | --- |
| `deep-research` | 收敛研究问题、文献综述、系统综述、事实核对 |
| `academic-paper` | 大纲、摘要、论文段落、修改、引用和格式检查 |
| `academic-paper-reviewer` | 模拟审稿、方法和贡献检查、复审 |
| `academic-pipeline` | 明确要求从研究到论文的完整分阶段流程 |
| `sr-screener` | 明确要求按既定纳排标准筛选文献记录 |
| `experiment-agent` | 实验规划、代码实验方案、统计解释和复现检查 |

直接说明任务即可，或者使用常见别名 `ars-outline`、`ars-abstract`、`ars-citation-check`、`ars-reviewer`、`ars-full`。如果 Codex 客户端截获以 `/` 开头的命令，用不带斜杠的普通文本别名。

写实验部分的示例：

```text
使用 $academic-research-suite，按 academic-paper 工作流帮我写论文实验部分。
研究问题：<一句话说明>。
输入：<数据集与划分>、<评价指标>、<基线和改造方法>、<主结果表>、<消融结果>、<图的路径>。
现在先给出章节结构与每节需要的证据，再用我确认的数据起草；请用简体中文，不编造实验或引用。
```

设计子实验的示例：

```text
使用 $academic-research-suite，按 experiment-agent 工作流检查我的 Agent + 遥感图文检索实验设计。
请区分主实验、消融、噪声鲁棒性和案例分析；指出每项实验要控制的变量、评价指标与复现信息。
已有材料：<代码路径、训练配置、结果表>。请用简体中文。
```

这套技能更适合“把研究材料组织成可靠的工作流”。若只有一个很具体的任务，例如核对几篇论文的 DOI，直接用专项技能通常更合适。涉及未发表论文、审稿材料或私人笔记时，先明确哪些材料可以交给外部服务；引用、数字和结论仍需对照原始证据检查。

## 五、Codex Autoresearch：跑可量化的代码迭代

[官方仓库](https://github.com/leo-lilinxiao/codex-autoresearch)。它用于反复执行“提出改动 → 修改 → 测量 → 保留或回退”。适合有稳定评估命令和明确数字目标的代码优化，不适合普通的一次性改文件任务。

启动前准备：

- 一个干净的、具名分支上的 Git 仓库，并配置 Git 提交身份。
- 一个可重复执行的测量命令。命令成功时，标准输出最后一个非空行应是有限数字，或包含指定数字键的 JSON。
- 指标名称、越大/越小越好、目标数值，以及允许修改的仓库相对路径。
- 可选的回归保护命令；它在基线时必须通过。
- 前台或后台运行方式。前台便于逐轮看改动；后台适合已充分确认的长时间任务。

下面是针对图文检索项目的提示词模板。尖括号部分必须换成**实际存在**的命令和数值，示例不代表 `agent-prior` 已有这些脚本：

```text
使用 $codex-autoresearch，为当前 Git 仓库规划一次可复现的验证集 mR 优化实验。
目标：把 mR 从实测基线提高到 <目标值>（越高越好）。
允许修改：<仓库相对路径>。
测量命令：<实际评估命令>；最后一行输出 {"mR": <数字>}，指标键为 mR。
回归保护：<实际测试命令，或写“暂无”>。
先检查 Git 状态、测量是否稳定及基线，再给我确认前台/后台方式和停止条件。
```

实验过程中，控制脚本会创建试验提交；指标没有改善或保护命令失败时，会用 Git 回退。结果记录在目标仓库的 `autoresearch-results/` 中。可以这样询问状态或历史，而不启动新实验：

```text
使用 $codex-autoresearch，查看这个仓库的实验状态和历史；不要启动或恢复实验。
```

```text
使用 $codex-autoresearch，为这个仓库生成实验历史 HTML 报告；不要改动实验。
```

**与 `agent-prior` 的提交习惯衔接：**这个项目要求“每次提交前先总结 git diff”。Autoresearch 的 `finish` 会自动提交试验，因此在该项目使用时，优先选前台运行，并明确要求 Codex 在每轮调用 `finish` 前先总结当前改动（包含已暂存、未暂存与新增文件）。后台无人值守模式无法保证逐次给人预览；若坚持每次提交前看摘要，就先不要在该项目启用后台模式。

## 六、常见问题

**输入 `$` 找不到技能？** 新开 Codex 对话；检查 `~/.codex/skills/<技能名>/SKILL.md` 是否存在。注意 Scientific Agent Skills 是多个独立名称，ARS-Codex 只显示 `academic-research-suite`。

**技能已出现但运行失败？** 先区分是技能未加载、依赖/模型未装、API 未配置、文件权限不足，还是输入材料不完整。把实际报错、使用的技能名和目标文件路径交给 Codex 检查，不要直接重装全部技能。

**能否把三套技能一次性全用上？** 可以按研究阶段组合，但每次任务优先指定当前目标和最合适的入口。无关技能同时介入会增加判断成本；Autoresearch 只在评估命令和目标数字明确时启动。
